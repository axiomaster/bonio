bonio的核心功能是伴随式AI，即伴随用户聚焦的窗口，那就需要理解用户窗口里的内容；
简单的方法是一直获取窗口截图，在server端进行分类、分析；但这样算力开销、时延、成本都很高；
我想增加一个分级处理逻辑：

1. UI Grounding：通过无障碍树/控件树/uitree，以及客户端ocr识别控件树中的图片内容，然后合并在一起，得到归一化的结构，比如

```
{
    "appname":"wechat",
    "title":"xxx的聊天页面",
    "link":"",
    "components":
    [
        // 控件/可见元素列表
        {
            "控件类型":"文本/图片/",
            "bbox":[] // bounding box坐标
            "content":"内容/图标描述..."
            "可操作性":"点击/滚动/选择/输入..."
        }
    ]
}
```
这一步时延应该是毫秒级，比如截屏+uitree+grounding 小于500ms;

2. 分类处理：分析UI Grounding输出的标准格式，通过分类模型快速得到页面内容，可以是多标签的分类；
这一步可以在client端实现一个轻量的分类模型，也可以在server端进行处理，但调用本地模型；

到这一步要求处理时延小于1s(包含grounding时延)，这一步完成后就可以给用户提供服务建议了；

用户的输入也可以在端侧进行分类；有分类则带上对应的prompt，无分类则带上上下文到第3步中进行处理；


3. 根据标签分类结果，推荐右键支持的功能列表；当然现在支持的功能比较少，后续通过插件扩展后需要根据tag对右键功能进行推荐排序；
另外，也可以根据页面内容，avatar进行主动建议，这里就需要使用server端模型了；server端模型可以是本地强力的模型，也可以直接用云端provider提供的模型；
