# OCR 文字识别功能设计

> 版本: 2026年5月5日
> 状态: 已实现

---

## 1. 概述

"识别文字"是 Bonio 右键菜单中的一个功能。用户可以在任意窗口上框选文字区域，Bonio 进行本地 OCR 识别，并将结果展示在一个独立窗口中。

### 与"圈一圈"的区别

| | 圈一圈 (AI Lens) | 识别文字 (OCR) |
|---|---|---|
| 框选 | 多矩形标注 | 单个矩形框选 |
| 处理 | 截图 + 标注 → 发给 LLM 分析 | 裁剪选中区域 → 本地 OCR |
| 时延 | 2-5s（网络 + LLM） | 30-80ms（本地 PaddleOCR） |
| 结果 | 打开输入框预填充 | 独立窗口（可编辑 + 复制） |

---

## 2. OCR 引擎选型

### 方案对比

| 指标 | Gemma 4 (LLM Vision) | PaddleOCR ONNX (选中) |
|------|----------------------|-----------------------|
| 时延 | 2-5s | 30-80ms |
| 成本 | API token 消耗 | 零成本（本地） |
| 准确率 | 通用模型 | 90%+（OCR 专项） |
| 安装包增量 | 零 | ~16MB（DLL + ONNX 模型） |
| 隐私 | 图片上传 | 完全本地 |

**结论：PaddleOCR ONNX**，时延低 100 倍，零成本，OCR 专项精度更高。

### PaddleOCR 模型

使用 RapidOCR 提供的 PP-OCRv4 ONNX 模型：

| 模型 | 文件 | 大小 | 用途 |
|------|------|------|------|
| PP-OCRv4 det mobile | `det.onnx` | 4.7 MB | 文字区域检测 |
| PP-OCRv4 rec mobile | `rec.onnx` | 10.8 MB | 文字识别 |
| 字典 | `dict.txt` | 26 KB | 中英文字符映射表 |

模型来源：ModelScope `RapidAI/RapidOCR@v3.8.0`

## 3. 架构

```
Desktop 前端
  │
  ├─ Lens 标注系统 (复用圈一圈/搜同款)
  │   ├─ 窗口截图 (PrintWindow FFI)
  │   ├─ 十字光标 + 红框标注
  │   ├─ 工具栏: 取消 / 确认
  │   └─ 确认：裁剪选中区域 → PNG base64
  │
  ├─ PaddleOCR 本地推理
  │   ├─ paddle_ocr_plugin.dll (C++ 封装, 12 KB)
  │   │   ├─ 动态加载 onnxruntime.dll (已随 Sherpa-ONNX 捆绑)
  │   │   ├─ det.onnx → 文字检测 → DB 后处理 → bbox 列表
  │   │   └─ rec.onnx → 逐 bbox 识别 → CTC 解码 → 文本
  │   ├─ paddle_ocr_bridge.dart (dart:ffi 绑定)
  │   └─ PNG → BGRA 像素转换 (dart:ui)
  │
  └─ OCR 结果窗口
      ├─ 独立 OS 窗口 (desktop_multi_window)
      ├─ 可编辑 TextField
      └─ 复制/关闭按钮
```

**不经过 HiClaw 后端**，OCR 在桌面端本地完成。AI 后端仅作为本地 OCR 失败时的降级方案。

## 4. 数据流

```
用户右键 → 识别文字
  │
  ▼
_enterLensMode(ocr: true)
  │
  ├─ ScreenCapture.captureWindow(anchoredHwnd)  // 截取锚定窗口
  ├─ 设置 _ocrMode = true, _lensActive = true
  └─ Avatar 窗口扩展 → 覆盖锚定窗口
  │
  ▼
用户框选文字区域 → 点击确认
  │
  ▼
_exitLensMode(submit: true)
  │
  ├─ _buildSearchSimilarCrop()
  │   ├─ 读取第一个 Lens rect → 按 DPI scale 转换坐标
  │   └─ capture.cropToPng(x, y, w, h) → base64 编码
  │
  ├─ IPC: avatarMenuActionWithData { action: 'ocr_text', pngBase64, windowTitle }
  │
  ▼
AppState._handleOcrText(data)
  │
  ├─ base64Decode → PNG bytes
  ├─ ui.instantiateImageCodec → RGBA pixels
  ├─ RGBA → BGRA 转换 (swap R/B channels)
  │
  ├─ PaddleOCR.recognize(bgra, w, h)  ──── 本地推理 (30-80ms)
  │   ├─ det.onnx: 文字检测 → DB 后处理 → 文本框坐标
  │   └─ rec.onnx: 逐框识别 → CTC greedy decode → 文本拼接
  │
  ├─ 成功: 直接展示结果
  └─ 失败: AI 降级 (chat.send + OCR prompt, 2-5s)
  │
  ▼
NodeRuntime.createOcrResultWindow(text)
  │
  └─ WindowController.create(bonioWindow: 'ocr_result')
      └─ OcrResultWindow: 独立窗口 (480×420)
          ├─ 可编辑 TextField
          ├─ 复制按钮 → Clipboard.setData
          └─ 关闭按钮 → windowManager.destroy()
```

## 5. 交互设计

### 5.1 框选工具栏

工具栏位置从右上角改为**跟随框选区域**：
- 有框选时：工具栏定位在最后一个矩形下方
- 无框选时：回退到右上角默认位置

### 5.2 识别结果窗口

结果窗口是**独立的 OS 窗口**（非 Bonio 内嵌弹窗），与搜同款窗口设计一致：
- 用户可以在原始窗口和 OCR 结果之间自由切换
- 窗口大小 480×420，可拖拽、调整大小
- 支持文本编辑 + 一键复制

## 6. C++ 原生插件

### 6.1 接口

```c
// 初始化：加载 ONNX 模型 + 动态加载 onnxruntime.dll
int paddle_ocr_init(const char* model_dir, const char* onnxruntime_path);

// 识别：输入 BGRA 像素，返回 UTF-8 文本
char* paddle_ocr_recognize(const uint8_t* bgra, int w, int h);

// 释放字符串
void paddle_ocr_free_string(char* s);

// 释放所有资源
void paddle_ocr_destroy();
```

### 6.2 ONNX Runtime 加载

不使用 ONNX Runtime SDK，通过 `LoadLibrary`/`GetProcAddress` 动态加载 `onnxruntime.dll`（已随 Sherpa-ONNX 捆绑）。关键函数：
- `OrtCreateEnv` / `OrtCreateSession` / `OrtRun` / `OrtGetTensorMutableData`
- 所有 Release 函数

### 6.3 后处理

- **DB (Differentiable Binarization)**：阈值 + 连通域标记 + 矩形框裁剪
- **CTC (Connectionist Temporal Classification)**：贪婪解码，移除连续重复 + blank token

### 6.4 构建

```bash
desktop\lib\platform\ocr\native\build.bat
# 产物: build\paddle_ocr_plugin.dll (12 KB)
```

## 8. 部署

```bash
# 1. 下载 ONNX 模型（一次性）
powershell -File desktop/tool/download_ocr_models.ps1

# 2. 编译 PaddleOCR DLL（一次性）
desktop\lib\platform\ocr\native\build.bat

# 3. 编译 + 打包 + 启动
scripts\build-and-run.bat --ninja
```

`bundle-hiclaw.ps1` 自动将 `paddle_ocr_plugin.dll` 和 `assets/ocr/*` 复制到 build 输出目录。

## 9. 后续优化

- **macOS 支持**: 编译 `libpaddle_ocr_plugin.dylib`，替换 `onnxruntime.dll` 加载路径
- **GPU 加速**: 使用 ONNX Runtime DirectML/CUDA provider 加速推理
- **多语言**: 切换 rec 模型支持日文、韩文、阿拉伯文等
- **检测模型升级**: PP-OCRv5 发布后替换模型文件即可，无需改代码
