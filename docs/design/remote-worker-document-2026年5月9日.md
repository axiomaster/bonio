# Bonio 远程打工人功能设计：微信远程获取主机文件

## 1. 业务背景与目标

Bonio 的下一步演进是成为桌面端的“远程打工人（Remote Worker）”。用户在脱离桌面设备（如通勤路上、开会时）可以通过微信向 Bonio 下达指令，让其在主机上执行操作并将结果返回给用户。

本设计文档聚焦于 Remote Worker 的 **第一个核心 Use Case**：**通过微信远程查找并获取 Bonio 所在主机的文件**。

用户故事示例：
1. **模糊查找**：用户在微信上对 Bonio 说：“把昨天写的那个微信集成的设计文档发给我。” Bonio 理解语义，在主机的知识库中检索并发送文件。
2. **具体查找**：用户在微信上对 Bonio 说：“把 D 盘 project 文件夹下的 bonio 需求文档发给我。” Bonio 精确定位该目录下的匹配文件并发送，如果超出默认共享范围，则主动向用户发起权限确认。

## 2. 界面与功能重构：记忆 -> 知识库

为了支撑本地文件的管理与检索，需要将 Bonio 桌面端原有的“记忆（Memory）”功能升级重构为“知识库（Knowledge Base）”。

知识库界面将分为以下 3 个 Tab 页：

### 2.1 Tab 1：笔记与碎片 (Personal Notes)
* **定位**：当前系统已经实现的记忆内容，包括右键“记一记”截取的屏幕信息、拖拽给 Bonio 的文本、以及通过“伴读”功能生成的阅读笔记。
* **交互**：瀑布流或卡片式展示，支持标签（Tags）和全文搜索。

### 2.2 Tab 2：会话萃取 (Extracted Knowledge)
* **定位**：Bonio 在与用户的日常交流中，自动提取出的核心知识、用户偏好、重要结论等。
* **机制**：作为长期记忆（Long-term Memory），在后续对话中作为 Context 自动注入大模型，让 Bonio 越用越懂用户。

### 2.3 Tab 3：本地文档 (Local Documents)
* **定位**：用户希望系统主动构建 RAG 索引的本地计算机文件目录。
* **交互**：
  * **目录管理**：用户可在此页面添加特定的文件夹（如 `D:\Work`）作为白名单。
  * **状态展示**：展示已加入目录的状态，包括文件数量、RAG 索引构建进度等。
* **权限说明**：配置在此处的白名单**仅用于构建索引和默认查询**。当用户在聊天中主动查询不在白名单范围内的路径时，Agent 不会直接拒绝或主动突破，而是触发单次权限确认流程（详见检索工作流）。

## 3. RAG 索引功能设计

针对用户在 Tab 3 配置的本地文档，Bonio 需要建立一套检索增强生成（RAG）体系。

### 3.1 索引构建工作流
1. **定时任务触发**：由 HiClaw 服务端的 Cron 定时任务模块定期调度执行索引更新任务。
2. **扫描与提取**：在 HiClaw 服务端扫描白名单目录，识别支持格式（`.txt`, `.md`, `.docx`, `.pdf` 等），并通过 C++ 本地库进行文本提取。
3. **内容切片 (Chunking)**：按照段落或固定 Token 长度（如 500 Tokens）将长文档拆分，并保留文件绝对路径、标题等 Metadata。
4. **向量化 (Embedding)**：调用配置的 Embedding 模型，将文本切片转化为向量表示。
5. **入库存储**：存入**专门的本地向量数据库**中，不使用简单的内存匹配或常规 SQL 数据库，以保障向量检索性能和规范性。

## 4. 检索与发送工作流设计

当用户通过微信客户端发起文件获取请求时，HiClaw 将解析用户意图，大模型将根据意图类型调用对应的工具。

### 4.1 场景一：模糊/语义查找
当用户提供的条件比较模糊，依赖对文件内容的理解时。
* **指令示例**：“发一下上周开会的项目周报” 或 “那个关于跨端组件的架构文档发我”。
* **工作流**：
  1. **提取 Query**：Agent 提取核心检索词（如“项目周报”、“跨端组件 架构文档”）。
  2. **向量检索**：调用新增的 `search_knowledge_base(query)` 工具。该工具在专属的本地向量数据库中进行语义检索。
  3. **匹配与确认**：工具返回匹配度最高的 Chunk 及其绝对路径。
  4. **文件发送**：Agent 获取到确定的绝对路径后，调用新增的 `send_file_to_wechat(filepath)` 工具。该工具将通过扩充后的底层 `wechat_adapter` 把媒体文件推送给用户。

### 4.2 场景二：具体路径查找
当用户明确指出了文件的存放位置或具备强规则的文件名特征时。
* **指令示例**：“把 D 盘 project 文件夹下的 remote-worker-document.md 发给我”。
* **工作流**：
  1. **提取路径**：Agent 提取出目标目录 `D:\project` 和目标文件名特征 `remote-worker-document.md`。
  2. **权限预检与确认**：
     * 系统底层校验 `D:\project` 是否存在于用户的白名单中。
     * 若**在**白名单内，直接放行。
     * 若**不在**白名单内，工具会挂起操作，Agent 会在微信中向用户询问：“路径 `D:\project` 不在您的共享范围内，是否授权我进行本次访问？”
     * 用户回复“同意/授权”后，获得单次访问 Token。
  3. **获取列表**：调用 `list_local_directory(path)` 工具获取该目录下的所有文件列表。
  4. **特征匹配**：Agent 从返回的列表中筛选出最符合特征的文件。
  5. **文件发送**：锁定文件后，调用 `send_file_to_wechat(filepath)` 进行发送。

## 5. 系统扩展需求汇总

为了支撑以上业务设计，系统架构需要做以下重点补充和开发：

1. **桌面端 UI (Flutter)**
   - 重构现有的 Memory 页面，实现具备 3 个 Tab 的知识库界面，并能配置和下发索引目录给服务端。
2. **服务端 Agent Tools (HiClaw/C++)**
   - 新增 `list_local_directory(path)`: 目录遍历，且内置权限越界提示与验证拦截逻辑。
   - 新增 `search_knowledge_base(query)`: 面向专属向量库的语义检索接口。
   - 新增 `send_file_to_wechat(filepath)`: 执行文件发送任务。
3. **核心引擎与后台任务 (HiClaw/C++)**
   - 选型并集成**专门的本地向量库引擎**（供 C++ 调用）。
   - 在 HiClaw 的 `src/cron/` 中增加负责构建/更新 RAG 索引的定时任务逻辑（包括文件读取和文本抽取解析库）。
4. **微信网络通信扩充 (WeChat Adapter)**
   - 目前 `WecomWsClient` 和 `IlinkHttpClient` 代码均仅支持纯文本发送，需要**紧急扩充**媒体上传（Media Upload）接口以及针对 `file` 类型的消息构建逻辑，使其具备真正向微信发送文件的能力。
