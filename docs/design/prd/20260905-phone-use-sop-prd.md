## 1. 背景与核心价值

用户在手机端（HarmonyOS）使用 AI 伴侣时，常常需要 AI 协助完成实际的手机操作（如“打开美团帮我买之前喝过的咖啡”、“帮我用剪映剪一个春节短片并分享”、“打开设置调节亮度”等）。

以往的自动化方案严重依赖电脑端中转，体验断层且响应迟缓。本项目通过在手机端原生运行 **`phone-use-harmonyos`** 结合 **SOP（标准操作规程）** 体系，实现：
1. **脱离 PC 的真机自主操作**：在手机本地直接理解屏幕内容并执行真实 UI 交互；
2. **SOP 经验注入**：规避大模型自由盲目尝试的高失败率，通过结构化 SOP 将多步骤任务的成功率提升至工业可用水平；
3. **敏感操作安全守卫**：在支付、外发信息等不可逆高危环节建立明确的“人类确认”安全边界。

## 2. 核心场景定义

### 场景一：创意视频生成（以“剪映”为例）
* **用户目标**：“帮我在相册中挑几张最近的照片，用剪映做个生活短片。”
* **SOP 介入策略**：
  - 传统盲目点击：大模型容易陷入复杂多轨道混剪，因缺乏非线性编辑经验而失败；
  - **SOP 导向操作**：强制引导模型采用“剪同款”模式（底栏 Tab 2），通过关键词搜索模板，再通过系统 Picker 批量选中素材，由模板自动完成特效与配乐。
  - **关键交互纠偏**：明确指导大模型“点击相册宫格右下角圆点为选中，点击宫格中央为预览”。

### 场景二：基于伴随记忆的订单复购（“再来一单”）
* **用户目标**：“帮我再点一杯上次喝的冷萃。”
* **SOP 介入策略**：
  - 提取伴随记忆（MSDP companion-memory）中保存的原始商品品名、规格、温度、糖度、门店；
  - 唤起外卖应用后直接搜索并精准加购对应规格；
  - **支付安全边界**：停留在待支付结算页，Avatar 提示：“已经帮您选好商品，请确认金额后手动点击支付~”。

### 场景三：系统功能与应用批量管理
* **用户目标**：“帮我检测当前屏幕是什么应用，打开免打扰并截个图。”
* **SOP 介入策略**：
  - 优先调用 `ohos-cli-tool` 原生底层 API（极速响应）；
  - 当涉及复杂动态界面时无缝交接给 `phone-use-harmonyos`。

## 3. 功能需求规格

| 编号 | 需求项 | 详细说明 | 优先级 |
|---|---|---|---|
| **F-01** | 端侧独立运行 | 不依赖任何外部 PC 或 USB 调试链路，纯端侧独立运行 | P0 |
| **F-02** | 视觉模型驱动 | 结合视觉多模态大模型，逐帧理解屏幕界面并输出标准化操作 | P0 |
| **F-03** | 完备动作支持 | 支持点击、滑动、长按、双击、文本输入、返回、主页、启动应用、等待 | P0 |
| **F-04** | SOP 模板集成 | 支持通过 DSH Skill 格式注入应用专项标准操作步骤（如 `cap-cut`） | P0 |
| **F-05** | 本地配置持久化 | 支持在 `/data/local/.phone-use-harmonyos/` 维护 API Key 与端点 | P0 |
| **F-06** | 步数与超时控制 | 默认单次任务上限 20 步（最大 200 步），超时安全退出 | P1 |
| **F-07** | 人工接管机制 | 支持 Ctrl+C / SIGINT 信号即时中断，保障设备控制权始终在用户手中 | P1 |
