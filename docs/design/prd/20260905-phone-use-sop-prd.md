## 1. 背景与核心价值

用户在手机端使用 AI 伴侣时，常常希望 AI 能够端到端代劳日常繁琐的手机操作（如“帮我点一杯常喝的咖啡”、“用剪映做个生活短片”等）。

以往的自动化方案要么依赖电脑端中转（HDC/ADB 延迟大且脱离 PC 不可用），要么因大模型在复杂应用中的盲目尝试而导致失败率极高。
本项目通过在 HarmonyOS 设备本地运行 **`phone-use-harmonyos`** 原生 GUI Agent，并深度集成 **`SopManager`（标准操作规程管理器）**，实现：
1. **端侧独立闭环**：纯端侧原生运行，截图、编码、大模型多模态请求与模拟操作均在真机本地无缝流转；
2. **SOP 知识引导**：支持内置 SOP 与外部 JSON SOP 配置动态加载，通过步骤细化与关键规则注入，大幅提升多步任务的完成率；
3. **敏感操作安全守卫**：在支付、外发等高危环节由 SOP 明确设定确认边界，杜绝越权操作。

## 2. 核心场景与 SOP 业务规范

### 场景一：瑞幸咖啡小程序历史订单复购（“再来一单”）
* **用户目标**：“帮我再点一杯上次喝过的咖啡”或“喝咖啡”。
* **SOP 业务链路**：
  1. 启动微信；
  2. 下拉任务栏或搜索进入“瑞幸咖啡”小程序；
  3. **防卡点规则**：主动识别并关闭新客/促销营销弹窗；
  4. 切换到底部【订单】页签（确认处于“历史订单”状态）；
  5. 定位目标饮品卡片，点击【再来一单】；
  6. **安全拦截边界**：自动加购并跳转至订单确认页，核对门店与规格；**严禁自动点击“立即支付”或输入密码**，到达待支付页即判定任务完成，提示用户手动完成支付。

### 场景二：剪映（CapCut）模板视频制作
* **用户目标**：“用剪映把刚才拍的照片做成视频。”
* **SOP 业务链路**：
  1. 优先采用“剪同款”模板流程（Tab 2），输入主题词查找模板；
  2. **相册 Picker 核心交互规程**：相册宫格组件点击正中为“预览”，**必须点击右下角小圆点**才能勾选素材；
  3. 导入素材后预览并点击右上角【导出】。

### 场景三：微信精准联系人发消息
* **用户目标**：“发微信给张三说晚上一起吃饭。”
* **SOP 业务链路**：
  1. 打开微信并点击顶部搜索框；
  2. 检索联系人并核对个人备注（防同名群聊误发）；
  3. 进入聊天窗口，输入内容并点击发送。

## 3. 功能需求规格

| 编号 | 需求项 | 详细说明 | 优先级 |
|---|---|---|---|
| **F-01** | 端侧原生运行 | 基于 HarmonyOS 原生 NDK 交叉编译，无需依赖 PC 链路 | P0 |
| **F-02** | 平台抽象层解耦 | 通过 `IPlatform` 接口抽象底层能力，支持鸿蒙与安卓多态扩展 | P0 |
| **F-03** | SOP 动态发现与加载 | 支持扫描 `/data/local/.phone-use-harmonyos/sops/*.json` 动态注册业务 SOP | P0 |
| **F-04** | 关键词智能匹配 | 依据用户输入的任务自然语言，自动模糊匹配对应 SOP 并注入引导 | P0 |
| **F-05** | CLI 显式 SOP 指定 | 提供 `--sop <NAME_OR_PATH>` 参数支持指定 SOP 名称或直接路径 | P0 |
| **F-06** | 两阶段 Prompt 注入 | 首轮注入完整工作流与避坑指南，后续每步注入简要状态 Reminder | P0 |
| **F-07** | 人工接管机制 | 响应 SIGINT (Ctrl+C) 立即安全退出，保障用户控制权 | P1 |

## 4. SOP 配置文件部署规范

- **设备端权威部署目录**：
  ```bash
  /data/local/.phone-use-harmonyos/sops/
  ```
  任何放置在该目录下的合法 JSON SOP 文件均会被 `SopManager` 启动时自动扫描并注册生效。
- **文件命名与内容规范**：
  - 命名：`<sop_name>.json`（例如 `luckin_coffee_reorder.json`）；
  - 必须包含：`name`, `keywords`, `target_app`, `description`, `steps` (`step_idx`, `name`, `instruction`, `expected_screen`), `traps_and_rules`。
